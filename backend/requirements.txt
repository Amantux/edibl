# foodcore — the food-reference library Edibl and myMeal SHARE (unit conversion
# that knows a cup of honey weighs 339 g, USDA portion weights, allergen rules).
# Zero runtime dependencies, and the USDA SR Legacy snapshot travels inside the
# wheel as package data, so this adds one package and no services.
#
# Pinned to a COMMIT, not a branch or a version range, deliberately. foodcore is
# consumed by two apps and SOP §8 says a change to shared code is a change to
# every consumer, made together. A commit pin is what makes that enforceable on
# THIS side: upgrading is a visible diff someone has to write, review and port —
# not something a rebuild picks up silently.
#
# Note the asymmetry, because it is real and not yet solved: myMeal is where
# foodcore's source lives and it installs its own working tree
# (`pip install ./foodcore`), so it has no pin to move in lockstep with this
# one. Editing foodcore in myMeal therefore takes effect there immediately and
# does NOT reach Edibl until someone bumps the SHA below. Until foodcore is
# extracted to its own repository that both apps pin, the obligation is a
# convention rather than a mechanism: a foodcore change lands with the SHA bump
# here in the same piece of work, or Edibl is running different shared code
# from its sibling.
