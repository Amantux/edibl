# foodcore — the food-reference library Edibl and myMeal SHARE (unit conversion
# that knows a cup of honey weighs 339 g, USDA portion weights, allergen rules).
# Zero runtime dependencies, and the USDA SR Legacy snapshot travels inside the
# wheel as package data, so this adds one package and no services.
#
# Pinned to a COMMIT, not a branch or a version range, deliberately. foodcore is
# consumed by two apps and SOP §8 says a change to shared code is a change to
# every consumer, made together. A commit pin is what makes that enforceable on
# THIS side: upgrading is a visible diff someone has to write, review and port —
# not something a rebuild picks up silently.
#
# The asymmetry this comment used to warn about is RESOLVED. foodcore no longer
# lives inside myMeal: it was extracted to github.com/Amantux/foodcore with its
# history intact, and BOTH apps now pin it the same way. Neither can edit the
# shared engine in place, so neither can drift ahead of the other — the
# obligation is a mechanism now, not a convention.
#
# Bumping: move the TAG here and in myMeal's backend/requirements.txt in the
# same session, after checking foodcore's own CI is green on that commit. That
# CI installs the wheel into a bare venv and asserts the dataset and rules
# subpackage actually shipped, which is the one failure a source checkout
# cannot see.
